# 产品文档

由当前 Codex 任务维护 PRD 与 Spec：PRD 定义产品，架构独立维护技术设计，Spec 按明确来源程序派生并接受手动反馈。默认一个 PRD、一个统一 Spec；既有分模块文档仅在用户授权重组时合并。先确认产物所属 Project、正式入口、本次范围、目标文件及当前确认状态。

## HTML 交付与文档同步

本节仅适用于已纳入产品文档流程的页面交付；纯源码抽取、隔离预览和未纳入该流程的功能试做不自动触发。上报适用范围以插件 HTML 完成协议为准。

创建或修改交付页面后，必须对照本轮变化依次核对 PRD 和 Spec；通过组件、JS 或 CSS 改变页面同样适用。受影响产品内容修订 PRD，技术变化修订独立架构，再按下文方法处理 Spec 待同步手改并重新派生，无需修改的说明依据；两份文档均完成核对、必要修订和一致性检查后，才能宣布本轮完成。文档缺失时按实际范围生成草稿，非产品页面说明不适用；冲突、写入失败或用户明确暂缓时如实说明未完成项。

HTML 验证按 [Spec 验收与变更影响](references/product-spec.md#36-验收与变更影响)，上报与评审沿插件协议；上报工具不可用也须继续文档核对，不把上报成功当作同步完成。只读查看及构建、测试偶然产物不触发；不自动追加工作台映射。

## PRD、Spec 与实现的衔接

正常顺序是 PRD → 工作台评审 → 本批适用架构设计或复用 → 程序派生 Spec → 已授权实现。已确认范围不重复评审，不要求无关范围冻结；用户要求联合草稿、直接生成 Spec 或暂缓评审时遵从。局部文档修订只处理目标及直接依赖；只请求文档时不开发页面。

- **PRD 复核与评审。** PRD 首次生成、重构或任何修订后，先按需使用 [prd-concise-cn](../prd-concise-cn/SKILL.md) 保真整理，再读取 [PRD 复核 Agent](agents/prd-reviewer.md)，按其模型、范围和只读权限启动独立子 Agent。原任务修正并交其复核，通过后才能交付、发布批注修订或进入下一阶段。仅格式修订不重跑表达编辑，仍复核改动；正文未变且已有同版本结果可复用。工具不可用或问题未解决时报告，不能以自检替代。用户评审的触发、等待、停止、发布和确认沿已安装插件协议，不另建门禁。
- **Spec 派生与同步。** [统一 Spec 方法](references/product-spec.md) 负责派生与手改回流。产品缺口回 PRD，技术缺口由 [架构 Skill](../software-architecture-design/SKILL.md) 写入独立架构。程序正常派生不调用内容自审或 Spec Reviewer；来源实质修订只复核受影响范围。已存在的非派生 Spec 保持原编辑和适用复核，未经明确迁移不覆盖。
- **实现反馈。** 本批 Spec 足以支撑实现时继续已授权工作。页面反馈改变产品结果，先修订 PRD，再同步 Spec；纯技术调整更新独立架构中的适用决定。HTML 完成仍核对两份文档。

## 写入与完成

保留无关正文、用户修改、有效 ID、引用、图片、人工 Map 和历史确认版本，不借局部任务迁移整套文档。冲突回到拥有该事实的文档处理；未知说明问题、当前处理和影响，仅影响安全、不可逆结果或核心闭环时阻断受影响部分。

页面只证明可见行为，源码只证明实现；医院、权限、接口、保存、审计及医疗规则须有对应依据，候选、仿真和局部认可保持原确定程度。按本次路径检查并报告修改、证据和未决项；不把格式、转换、映射保存、产品确认与运行验收混为一项结果。
