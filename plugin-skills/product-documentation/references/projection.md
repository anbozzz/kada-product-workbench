# Markdown 到工作台数据

仅在需要生成或刷新工作台数据时读取。输入为已选定的 Markdown Spec、可用页面证据及调用方的输出约定；输出为 schemaVersion `0.1` 的工具侧 bundle。纯转换不修改 PRD、HTML、Spec 或人工 Map，不启动工作台。调用本路径不进入本 Skill 的 PRD／Spec 设计、架构、独立内容复核或评审流程；历史正文忠实转换，不以新文档标准强制重写。

## 内容转换

全量转换须完整读取原始 Spec，保留全部业务节点、稳定 ID、类型、模块与节点顺序、原文字段标题和内容，以及直接 relation。不筛选普通操作，不合并或拆分节点，不借历史补充型 Spec 的转换增补需求。

每个 `contentBlocks` 元素只有稳定块 ID、非空字段标题和一段 Markdown 内容。列表、表格、代码与多行内容仍是原文，不变成嵌套业务对象；不补固定业务字段。`fields` 只兼容旧数据，`statement` 需要时取自已有正文，不创造新定义。

工程章节与非节点说明保留在原 Markdown，不变成业务节点。bundle 不是整份 Spec 的无损副本，不能用它重建并覆盖整份正文。

## 页面证据

- 只有实际可核验的页面才进入顶层 `pages`，节点用 `pageId` 引用；拟定页面和路由留在 Markdown，无页面证据时 `pages` 为 `[]`，`pageId` 按调用方 Schema 省略或设为 `null`，不写空字符串。
- `parentPageId` 只来自已证明的父页面到子页面导航。标题、章节顺序、路由相似、DOM 嵌套不证明父子关系；多父导航不强塞单一父节点。
- 页面标题、`routeHints` 与 `anchorHints` 可作为候选定位信息，不能反向改写正文、拆分节点或证明后端规则。
- 旧 module 内 `pages` 按平铺根页面兼容；无页面元数据仍可转换，不编造归属。弹层可作页内场景，不要求每个状态都能直接打开。

## 校验与输出

依据插件的 `schemas/product-spec-bundle.schema.json` 及实际校验器检查结构、ID 唯一、PRD 引用、关联目标和内容留存；仅返回投影结果的调用使用其指定输出 Schema。Spec 文档身份及来源类型、确认状态保持原值。只有 `SURFACE` 和 `ACTION` 可关联 DOM，其余节点供直接关联阅读。

按调用方约定返回 JSON 或写工具数据/缓存目录；不在 Project 新建正式 JSON 正文。进入工作台或应用修订前重新核对 Markdown revision，来源变化时重新读取，不能用旧投影覆盖新正文。报告转换与校验结果；转换成功不表示需求完整、映射已确认或产品已验收。
