# 工作台映射与查看

仅在用户需要进入工作台时读取。工作台同时呈现“页面到 PRD 章节”和“Spec 操作到页面元素”的关系；两类关系分别保存。完整 Spec 的独立文档编辑不属于该界面能力。

## 进入现有工作台

1. 优先使用本 Skill 随包的 `scripts/cli.mjs` wrapper；共享源没有 wrapper 时使用 Workspace 的 `apps/interactive-product-spec/cli.mjs`。继续已有会话和地址，不另建工作台。
2. 确认 HTML 或开发页面可访问、必要资源齐全，以及 PRD、Markdown Spec 和 Map 来源。Spec 可选，不能要求只有 PRD 的用户先生成 Spec。
3. PRD 须通过应用的 `可映射PRD-v1` 校验。失败时只读展示原件，停止绑定，不创建 Map。独立项目中心只有在用户明确发起后，才创建可见 Codex 任务，由 `product-documentation` 在 `drafts-documents/` 修订标准化草稿；沿既有模型选择和受限 Project 写权限执行，不复用只读投影任务。任务中断、失败或复查不通过时，保留原选择。
4. 有 Spec 时检查节点能回到 Markdown 定位、关联 PRD ID 存在。缺少或过期的 bundle 按 [数据投影](projection.md) 在同一任务生成并校验，再继续；不让用户另建转换任务。已有历史 Spec 可忠实映射，不借映射扩写内容。
5. 用户选择 `map` 进入可编辑映射，选择 `review` 只读查看。由等待中的 Codex 发起 Spec 修订时使用现有 `--gate` 会话，在同一地址确认来源后进入草稿编辑。

## 操作与保存

| 目标 | 操作及写入范围 |
|---|---|
| 页面关联 PRD | 从“相关 PRD”选择章节；只保存 `prd-map.json`，该文件与 PRD 同目录、一起冻结。缺失时须用户明确确认创建 |
| Spec 关联页面元素 | 只关联 `SURFACE` / `ACTION`。人工映射优先；候选需用户确认，或用现有点选、拖拽选择真实目标。自动候选不写入 Map |
| 保存 Spec 映射 | 校验 `productSpecId` 与 bundle 一致；缺失时先用工具侧空映射，不静默在 Project 建文件。建立、调整或解除后由工作台携 revision 保存 `spec-map.json`，拒绝版本冲突 |
| 普通会话修改节点 | 一次只保存一个节点；校验 Markdown 与投影 revision，原子写回本地 Markdown 并刷新 bundle，不依赖 Codex 连接 |
| `--gate` 修改节点 | 先保存会话草稿；用户“提交 Codex”后返回节点级 before/after，等待中的 Codex 校验原文版本后才应用补丁 |
| 只读查看 | 不新建、更改或保存映射，不写 Spec，也不增加审批或逐项打勾状态 |

没有 Spec 时，合法 PRD 可独立进入页面工作台：可编辑模式阅读全文并关联章节，只读模式显示当前页面已关联章节；无关系时显示空状态。PRD 正文修改仍由文档 Skill 承接。

## 核对本次范围

检查标记是否落在真实功能上，操作反馈是否符合节点正文，相关规则与来源是否可信。公共约束须直接关联才算适用；同模块的其他规则不能自动套用。页面可见不证明后端、权限或医院口径。

动态组件未显示或当前路由不同，先进入正确场景再检查，不因暂时找不到目标重新绑定。定位错误时保留当前节点，手动进入正确场景后用“在页面上选择位置”或“重新关联”；不执行候选动作来猜测路径。

映射保存只证明关系已保存；普通节点保存只证明该节点通过版本检查并写回；gate 提交只证明差异已返回 Codex。分别说明实际结果，不据此确认产品规则、后端实现或用户验收。
