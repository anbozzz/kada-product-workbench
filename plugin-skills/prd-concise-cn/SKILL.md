# 中文 PRD 可读性编辑

处理已经成稿的中文 PRD。先守住需求含义，再减少阅读成本；不把编辑任务变成产品设计。

## 与产品文档编写的分工

- 新增或修订产品需求先交由 `product-documentation` 完成；本 Skill 在需求成稿后执行。
- 只有表达编辑任务时直接读取现有 PRD，不重新从代码推导产品，也不强制重跑需求生成。
- 延续当前 Project 的唯一文档入口、目录和确认状态；不默认生成第二份「精简版」，不因研发认可表述而将整份文档标为已确认。
- 保留文档外层结构、业务功能域和功能层级、稳定 ID、来源绑定、图片、图示、链接和固定文案；功能内标题可按下述方法调整。隐藏映射标识不是冗余文字；不改写页面映射或确认记录。

## 判断哪些表达需要调整

对准备删改的句子问：删掉后，读者会不会对「谁、什么对象、何时、做什么、结果、限制、例外」产生不同理解？会则保留或等价改写。

- 删除只复述标题的用途介绍、没有产品结果的「进入后查看、核对后选择」、宣传性评价和写作过程说明。
- 同一规则在功能说明、入口、步骤、规则中重复出现时，保留一个完整定义，其余只保留本页面的差异或短引用。
- 不把跨页面相似规则直接合并。先核对适用对象、前提和例外，只有完全相同时才去重。
- 功能说明保留独有的目的或边界，不为保留模板而换句话重复步骤；也不能为了短把整章变成脱离上下文的关键词表。

## 改写方式

- 在授权范围内允许整段重写、调整叙述顺序、拆合段落和改写功能内标题。先组织完整操作，再处理句子；不要求先逐类生成再压缩。叙述顺序可变，业务执行顺序和规则作用范围不可变。

- 操作写清场景、条件、动作与结果；限制写对象、条件与约束。主体、对象和时点仅在相邻正文能唯一确定时省略，不把不同场景压成无前提的连续动作。
- 调整操作归属或标题时，读取 [单项功能设计](../product-documentation/references/standard-product-document.md#单项功能设计)，确定内容位置及编号，并参照其中完整示例；不强制保留功能内分类栏目，也不套用同一组操作标题。
- 专有名词保持一致。保留「必须、仅、不得、至少、同时、之前、之后、可能、待确认」等改变逻辑或确定程度的词。
- 不将按姓名搜索改成模糊搜索，不将保存改成自动保存，不将「可以」改成「必须」，不把例子写成唯一允许值。
- 数字、单位、角色、字段、默认值、触发条件、成功和失败结果、取消与恢复、历史保留和不可逆行为均需保真。
- 对象身份、数据权威来源、模块职责与依赖、页面唯一性、产品质量指标和版本影响同样属于有效需求，不能以“精简版”为由删除；精简在 PRD 内整理表达，不将必要产品定义移往 Spec，也不以 Spec 引用替代这些定义。
- 表达冗余：在含义不变的前提下直接删除、合并或改写。
- 原文省略：只有从当前正文能唯一确定主体、对象或指代时才补明；补明后可以更长，不为缩短而保留歧义。
- 设计缺失或矛盾：存在多个合理解释，或必须新增条件、结果、权限、状态或继续方式才能写清时，不作为文字编辑处理。指出原位置和缺少的决定；在产品文档生成或修订流程中，由当前任务返回 [product-documentation](../product-documentation/SKILL.md) 处理后再继续编辑。仅获授权表达编辑时保留该处未知，完成其他可保真编辑，不擅自补设计。

## 执行与验收

1. 固定编辑前的当前文件快照，通读全文；按章节记录要保留的业务含义，不从旧对话覆盖当前文档。
2. 按上述三类处理本次范围：先辨认歧义和设计缺口，再把同一操作的条件、交互、结果及局部分支组织完整，补明可唯一还原的省略，最后去重和整理句子。产品流程补齐定义后，以补齐后的正文为编辑基准，不把新增设计计作编辑造成的语义变化。保留近期用户修改。
3. 对照原稿逐章做三轮检查：
   - **保真**：角色、范围、条件、否定、例外、数值、状态及待确认项是否一致。
   - **可读**：编辑后读取 [PRD 交付检查](../product-documentation/references/standard-product-document.md#5-交付检查)，复读完整功能。若须借原稿或聊天才懂，补回场景、对象及条件；有歧义回产品设计，不以更短判定更清楚。
   - **结构**：外层标题层级、稳定 ID、来源绑定、图示、图片、链接及局部引用是否仍有效；移动内容后检查共同前提和例外的适用范围。正文变化须沿原流程核对 revision 与批注定位，ID 未变不等于旧页面映射、批注或 Spec 已重新验证。
4. 不设目标压缩比例。用户要求压缩或字数对比时，同口径报告编辑前后正文字符数（不含空白、隐藏注释、代码块、图片地址和版本历史）；伴随产品修订时，区分设计增补与表达整理，不用总字数增减判断精简成效。没有安全精简空间时保留原文。
5. 独立表达编辑任务在写入后，接续 [产品文档流程](../product-documentation/SKILL.md) 的独立 PRD 复核；由产品文档流程调用本 Skill 时交回该流程，不重复启动复核。通过后交付当前文档、实际整理及保留边界；统计按上一步适用范围报告，不以格式或字数证明语义等价。

## 最小试验

- 「输入姓名并点击搜索后展示匹配患者」可以压缩主语，不能新增模糊匹配、实时检索或自动选择结果。
- 「仅创建者可删除，且已上报后任何人不可删除」必须同时保留角色与状态限制。
- 「评分新增历史记录；意见修订仅留最新内容」不得合并成统一保留历史或统一覆盖。
- 操作已经连续清楚、指代明确且没有冗余时允许原样交付，不为体现编辑工作而改写。
