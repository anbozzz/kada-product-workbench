# 技术架构设计：可追溯 Spec 派生与手改回流

状态：implemented。范围：用户于本任务确认的 PRD、独立架构、派生 Spec 与既有手动编辑闭环。历史 Spec 和人工映射不自动迁移。

## 原因与责任

PRD 拥有产品行为，架构拥有技术设计；Spec 是按明确来源生成的研发阅读视图，同时接受用户手动修订。程序负责原文提取、身份和版本检查，Agent 只在来源设计或手改同步时判断语义。正常派生不调用模型，不重复进行业务全文复核。

## 来源与输出

本版在 PRD 中使用一个 spec-view JSON 注释登记已有节点身份、来源章节 ID、模块和实际页面，以及明确的本批范围外原因；声明只有引用与展示身份，不存储第二份业务正文。PRD 的 prd-section-id / spec-source-id 和架构的 architecture-id 紧随对应标题，完整章节成为可引用单元。结构标记须在源文档维护；不能在生成时猜测节点或规则归属。

程序生成现有 MODULE/节点 Markdown，原章节以引用块呈现，保持正文、列表、表格与代码。原页面、节点和 Map 格式沿用；没有实际页面时不登记页面。编辑器原有逐节点直接写回及 gate 回传保持原样。Spec 源文件含派生标记；工具侧保存一个当前派生基线、来源版本与绑定，以及当前待同步差异，不建立第二份正式文档或增长式历史台账。

## 手改与回流

工作台及外部编辑器都可以修改 Spec。spec-changes 对比持久基线与当前文件，返回节点或文档框架的 before/after、来源与版本；多次编辑汇为当前净差异。读取来源、用户提交或执行文档同步时处理，不因每次保存启动 Agent。

Agent 根据差异修订 PRD、架构或来源中的展示声明，按实际影响复核；原确认版保护规则不变。先预览重新派生结果，再提供逐项 changeId、更新的具体来源 ID 与承接依据，以及精确 Spec/源版本和候选版本回执。程序核验结构、来源块确已变化及版本；回执不是语义正确、产品确认或用户验收的证明。没有被源文档承接的修改保持待同步，禁止用 force 开关丢弃。

## 一致性与恢复

来源和输出限制在显式 Project 内，不能互相覆盖；缺少基线时不能覆盖已有文件。生成锁串行化本工具写入，发布前复读输入；外部编辑器仍须遵守同一文件协作，无法承诺跨进程任意写入的数据库级事务。工具侧先记录待发布版本，移动原 Spec 到一个有版本记录的恢复副本，再以排他方式放入候选，最后提交基线；原副本保留到下次安全发布；中断后依据原版本/目标版本恢复，有额外手改时保留并报错。删除源或 Spec 不自动重建。Map 不由派生器写入。

## 明确不改及否决

不修改工作台页面、普通保存策略、gate 的 applyTarget、PRD 批注确认、HTML 上报或现有 JSON 投影合同。不自动迁移 MDT 等业务 Project，不修改安装缓存。否决模型重新组装正文、无基线覆盖、每次保存启动 Agent、派生成功视为确认，以及创建第三种 Spec 提交策略。

## 验证

覆盖原文留存与既有解析、缺引用/未声明范围、正常重复派生、工作台/外部手改、累积净差异、源和 Spec 并发变更、回执漏项/过期/未改源、发布恢复、路径越界、原来源和 Map 不变。CLI、现有 Node 测试及适用工作台回归分别报告。

## 来源标题完整性修正

2026-09-13，状态：implemented。架构 Skill 与来源标记联合复核发现：未标记的技术决定若只写在标题中，会被原完整性检查无条件跳过。修正范围仅为来源覆盖检查：首个一级文档标题、已标记章节内的标题，以及确实包含已标记后代的分组标题保留；其余未标记标题拒绝派生，已生成 Spec 和基线保持不变。

不改变来源 ID、标题截取边界、节点和 Map 格式、手改回执或历史 Spec 保存；不强制旧非派生文档补 ID。否决在 Python 架构格式校验器重复实现来源合同，也不依据标题文字猜测它是否属于技术决定。回归覆盖标题独占语义、分组与空分组、已标记标题、拒绝刷新时保留原 Spec，以及现有手改同步与恢复路径。在隔离源码副本运行项目 `npm run verify`，192 项 Node 测试及全部既有浏览器旅程通过；新增来源标题测试 4 项，派生专项合计 14 项通过。新架构八章模板及完整示例另通过真实派生、节点与公共来源手改回流检查；Python 格式校验回归 7 项通过。

程序按结构识别包含已标记后代的分组，不判定标题的业务含义；分组标题若承载技术决定，作者须将其纳入已标记来源并复核。自动结构通过仍不能证明来源语义完整。本轮不引入额外分组标记、自动复制祖先正文或重写来源关联。
