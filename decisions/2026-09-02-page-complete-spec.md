# 按实际页面完整承接需求的 Spec

- 日期：2026-09-02
- 状态：用户已确认方向，实施范围为共享生成规则与本工作台的兼容保障

## 原因与决定

研发不再以阅读 PRD 为前提。原“只补充复杂流程和关键节点”的收录原则会主动排除 PRD 已说明的普通操作，不能满足当前交付目标。Spec 改为按实际页面组织、完整承接本次范围内的产品要求；研发从页面上的 Action / Surface 及其直接关联说明即可理解展示、操作、条件、结果和例外。

PRD 保留需求来源与范围解释，Spec 保留来源版本和章节引用并提供自足的产品说明；二者不独立创造冲突规则。页面只证明可见交互，不证明后端、权限或医疗事实。来源修订在 generate 流程中按范围更新，map/review 不擅自改造已有文档。

## 边界与明确不改

- 覆盖所有业务操作，包括普通操作、输入选择、取消返回、弹层和状态相关操作；重复列表项可共用同一动作，不逐条业务数据制造节点。
- 页面仍只映射 ACTION / SURFACE；规则等非页面节点通过明确关系就地阅读，不能以同模块未关联节点代替适用规则。
- PRD 有要求但页面缺失时保留产品说明并标记缺口；页面行为无来源时保留 candidate / simulation / tbd，不编造事实。
- 保留 PRD 独立阅读、来源选择、两类 Map、编辑回写、评审导出与确认边界；不改 Schema、路由、存储职责或业务项目 PRD/HTML/Spec。
- 不自动升级已有补充型 Spec，不重置既有稳定 ID 和人工映射。

## 否决方案

- 只补一批关键节点：仍会把普通操作排除在生成标准之外。
- 复制整份 PRD 或仅放章节链接：前者重复维护，后者仍强制研发跨文档阅读。
- 新增“完整 Spec”模式或第三类页面标记：现有页面树、内容块和关联约束可承载，无需平行流程。

## 实施与回归

修改共享 Skill 的入口、收录标准和默认提示；映射投影忠实保留全部已有节点，不自行筛选关键性。投影服务比较来源中的标准节点 ID 与类型，在新生成及缓存复用时拒绝漏节点、额外节点或类型变更；此检查不宣称证明 PRD 产品语义完整。

技术架构检查：沿用原模块、接口、数据与写回链，仅调整内容生成约束及投影校验，无需新的技术架构设计。

回归覆盖：普通操作和共享规则留存、页面章节下逐节点编辑、错误投影不覆盖上次有效结果、PRD 独立入口、原绑定/重绑/解除、动态场景恢复、关联约束阅读和只读导出。使用项目统一 verify 入口；语义覆盖另用真实生成样例检查，不以节点数量冒充产品验收。
