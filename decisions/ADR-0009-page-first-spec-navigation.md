# ADR-0009：先导航页面，再定位元素

## 背景与问题（Context and Problem）

真实 MDT 工作台点击个人对话时，query 与 hash 被一起赋给 URL.search，导致 hash 被转义为参数内容。中心业务群的页面导航又依赖其中一项旧组件映射，组件多命中会阻断整页。未绑定节点先搜索当前 DOM，容易被其他页面的同名输入框截获。

## 决策驱动因素（Decision Drivers）

- 用户已授权修正地址解析、解除组件校验对整页导航的阻断，并在正确页面内定位。
- 复用页面树、现有 routeHints 和人工 Map，不另建地址注册表、页面或工作模式。
- 保留人工映射、动态场景的手动进入能力、只读权限、详情标签和未保存内容。

## 候选方案（Considered Options）

1. 继续调整跨页候选置信度：不能修复错误地址，也无法解释为何已知页面被按钮匹配阻断。
2. 先解析并打开显式页面地址，再在页面内定位：采用。导航与元素匹配分别反馈。

## 决定结果（Decision Outcome）

页面展开使用第一条有效本地 routeHint 作为默认地址，不以任意子节点 Map 为前提；仅缺少路由时兼容经原校验可恢复的人工地址。hash/query 共用一个完整 URL 解析函数，解析前清除入口的旧查询与片段，避免跨场景残留。

未绑定节点先进入所属页的默认地址，再计算页内目标；无明确路由时仅辅助当前页，绝不遍历业务控件。已有人工映射优先恢复其实际目标；校验失败而所属页有明确地址时，仍可打开所属页，但不冒充已定位组件、不覆盖映射。评审模式也能打开明确页面并预览可靠位置，只读权限保持不变。

导航和定位不得执行目标业务动作或写 Map。异步导航支持取消，超时、路由恢复失败、元素缺失各自反馈，不改详情标签。开发地址保留当前页辅助定位，不新增跨页自动导航。

## 后果（Consequences）

### 正向影响（Positive）

- 页面可达不再依赖元素匹配分数；同名控件只在正确页面内比较。
- 删除跨页候选试探与路由候选缓存，减少两套导航决策。

### 负向影响与风险（Negative / Risks）

- 选中的显式页面能打开，但隐藏元素仍可能需要用户进入对应状态。没有可恢复地址的动态对象仍由原型负责，不由工作台保存业务快照。
- 多路由按文档顺序使用默认入口；本轮不重新生成 MDT 投影、不实现文档刷新、不修改业务原型或人工 Map。

## 验证遵循情况（Confirmation）

- 完整 query/hash、已有入口查询清除、两个会话同名输入框、旧组件多命中、元素缺失、连续快速选择、刷新及评审只读路径。
- 原无精确路由动态场景、人工绑定与保存、标签保持、页面标记、画布、PRD 和导出通过统一 verify。
- 在原工作台地址核对两个 MDT 页面，并在独立目录运行构建产物。
