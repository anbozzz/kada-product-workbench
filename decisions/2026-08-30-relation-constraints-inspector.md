# 非 DOM 约束通过右侧详情展示

## 原因

左侧树的任务是找到并管理能落到页面 DOM 的 `SURFACE` / `ACTION`。把规则、状态、权限、事件、验收和外部依赖混入左侧，会让“未映射”与“无需映射”混淆，也会抬高用户定位真实页面节点的成本。另一方面，只展示当前节点的直接关系会漏掉对整个模块持续生效、但没有显式 DOM 关系的公共约束。

## 决定

- 左侧树继续只展示 `SURFACE` / `ACTION`，且映射完成率只统计这两类节点。
- 右侧详情保持“操作定义｜关联约束（数量）｜页面映射”。
- “关联约束”只展示非 DOM 节点，分为“当前节点关联”和“模块内其他约束”，并按节点类型分组。
- 约束卡片默认显示类型、标题和摘要，点击后在当前 Tab 原位展开完整定义。
- 每个非 DOM 节点明确标记“无需页面映射”，不提供拖拽、映射状态或页面定位入口。

## 明确不改

- 不创建第二棵 Spec 树，不把关系卡片变成页面导航。
- 不推断新的业务关系；当前契约不能证明未直接关联节点对整个模块生效，因此第二组只表示同模块内其他非 DOM 节点的可见性分区。
- 不修改 Spec Schema、关系类型或 `spec-map.json`。

## 回归检查

- 左侧源码和实际页面都不显示非 DOM 节点，也不把它们计入映射完成率。
- 右侧能区分两类约束、按类型展示、键盘展开，并保持当前选中节点。
- 展开态显示完整定义且明确“无需页面映射”。
- 真实页面截图覆盖默认态、展开态和窄面板边界。
