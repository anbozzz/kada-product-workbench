# ADR-0006：在现有工作台通过 MCP 返回 PRD 批注

## 背景与问题（Context and Problem）

用户需要在阅读 PRD 的位置填写意见、批量交给原 Codex 任务，并查看修订结果。原生 Markdown 编辑或添加到对话不等于这个闭环。HTML 完成上报只选择文档路线；Skill 完成 PRD 草稿后才显式开启评审。

## 决策驱动因素（Decision Drivers）

- PRD Markdown 仍是唯一正文来源，只有原任务及 product-documentation Skill 修订它。
- 没有 Spec、没有 PRD 页面映射，也能阅读和批注完整文档。
- 复用工作台、PRD 阅读器、HTML 画布及图片/流程图；不覆盖主干及安装版本。
- 批注绑定文档 revision、引文、源行及章节，外部修改不得静默重定位。

## 候选方案（Considered Options）

1. 原任务调用 MCP 打开工作台、等待批注、发布新版，再等待下一轮。
2. 工作台新建 Codex 任务执行修订：无法满足回到原任务，否决。
3. 复用 Spec 的一次性退出 gate：无法保留同一地址的多轮预览，否决。

## 决定结果（Decision Outcome）

采用方案 1。新增独立 PRD feedback 服务拥有批注和轮次，不拥有正文及 Map。MCP 进程维护会话，HTTP 只组合用例，前端经 API 模块调用。批注保存在工具状态目录；显式提交后原任务的等待调用返回。同一批次可重读，不重复提交；发布新版须指定待处理批次、验证合法 PRD 和当前 revision。结束评审不改变 PRD 确认状态。

页面布局（用户试用后修正）：现有顶栏和 HTML 画布不变，PRD 统一复用原可拖宽抽屉（完整正文／差异），不再为批注增加固定双栏。选中文字后在选区旁打开评价浮窗，填写后添加到下方待发列表；底部负责汇总、预览、整批补充说明和一次发送。否决“选中即清除选区、跳到底部填写”的路径，因为它打断逐段阅读。既有批注仍可预览、编辑、删除，搜索、目录、图片和 Mermaid 保留。

浮窗复用现有 Radix Popover，以浏览器 Range 为运行态锚点，随正文滚动和抽屉拖宽重定位。Range 不进入存储或 API；未完成评价与既有草稿同属标签页，关闭浮窗不丢字，重新选区时保留已写评价。恢复时按原引文与行范围找回位置，找不到时保留意见并提示，不把评价挂到别处。仅显式发送进入原有原子提交路径，前端添加评价不写 PRD 或服务器。回归须证明浮窗紧邻选区、焦点不去底部、连续多处独立评价、键盘/输入法、取消和恢复，以及原画布控制仍可用。

一次发送携带完整批注并在服务内校验、原子落盘及提交；否决前端串联保存／提交，因为断网会产生已保存却未发送的中间状态。旧 save/submit 调用保持兼容，状态结构不迁移；原任务、文档和 Map 所有权不变。发送使用稳定批次 ID，丢失响应后重试不重复提交。编辑中的选区及意见暂存当前浏览器标签页，提交成功才清空；存储不可用时明确提示。跨地址恢复仍以工具侧记录为准。

明确不改：Stop 触发规则、HTML 交付去重、两种 Spec 提交策略、PRD 内容标准、两类 Map、项目中心的新任务生成路径。浏览器不可写 PRD，不允许任意文件路径写回。会话仅监听 loopback；修改接口校验来源及会话令牌。

## 后果（Consequences）

### 正向影响（Positive）

- 用户留在一个工作台完成多轮评论与新版阅读；现有工具职责不被混合。
- MCP 直接返回调用它的原任务，不需要推测任务 ID，也不注入另一任务。

### 负向影响与风险（Negative / Risks）

- 原任务必须保持等待并按协议发布新版；断线只保留反馈，不假称已完成修订。
- 批注含产品内容，工具状态仅用于本机恢复，不进入只读导出或 Map。
- 跨进程恢复需要原任务明确重新打开同一来源；已提交意见保持原版锚点，不自动迁移。

## 验证遵循情况（Confirmation）

- 服务测试：选区锚点、重复提交、过期 revision、批次不匹配、无变化发布、结束及恢复；所有操作不写正文。
- MCP/HTTP 测试：等待返回同批次、提交后发布、外部来源拒绝、只读导出无令牌。
- 浏览器：从真实工作台打开无 Spec/Map 的 PRD，拖宽抽屉、连续选区、引用与发送预览、一键发送、失败及刷新保留草稿、新版全文／差异、多轮与结束；原阅读／图片／Mermaid／映射旅程回归。
- 完成时运行 npm run verify；技术验证不代替用户验收，独立分支不合并、不升级安装。
