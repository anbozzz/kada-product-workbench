# 可冷启动路由作为页面精确定位前提

> **状态：已取代。** 产品经理制作的低保真 HTML 不负责恢复任意运行时业务状态；关联事实与自动跳转能力必须分离。现行决定见 [`2026-09-01-binding-validity-navigation-capability.md`](2026-09-01-binding-validity-navigation-capability.md)。本文件只保留旧路线及其失败原因。

## 原因

工作台已经能够在用户当前手动到达的页面中确认 DOM 组件，但部分单页演示把独立页面继续藏在粗粒度路由下。例如 MDT 会诊群、视频会诊、会诊结束和会诊记录都共用 `#S007`，具体页面只由内存中的 `meetingView`、当前会诊和当前轮次决定。用户当次操作可以到达目标，刷新或重新打开同一地址却无法重建页面。

此前增加的自动场景书签把用户浏览过程中的安全点击步骤随映射保存，再从粗路由回放。这条路线在简单页面可用，但在真实会诊流程中会记录绕路、返回和位置型按钮；其起点本身也可能依赖已经丢失的内存状态，因此只是把“当前页面未找到”推迟成“路径回放失败”，没有解决精确定位。

## 决定

- 原始 HTML 对可独立评审、可独立绑定的页面或关键场景负责提供可冷启动路由：把该地址复制到新窗口后，必须直接重建同一演示场景。
- 人工映射仍只保存用户确认时的精确 URL、selector 和语义指纹。工作台不保存、搜索或回放用户点击历史。
- 自动定位只在来源页面提供了精确路由时成立；没有可靠候选或精确路由时保持用户当前选择，允许用户在中间页面手动进入目标后绑定。
- 人工绑定保存当时页面已经暴露的精确路由。已有绑定的组件在用户手动进入后再次准确出现，且页面地址已经变得更精确时，只更新该绑定的页面地址，不改变用户确认的组件。
- 可控演示原型通过 URL 中的稳定演示场景参数恢复所需本地仿真状态；这些参数不是产品功能编号、真实业务主键或正式接口合同。
- 页面地址相同且目标缺失时，按真实映射异常处理，不再因为存在点击书签而隐藏为 `out-of-context`。

## 明确不改

- 不要求工作台猜测患者、会诊、轮次或表单的业务含义。
- 不通过刷新后验证、DOM 快照、Local Storage 快照或页面点击遍历证明路由可恢复。
- 不执行被绑定组件，不把页面仿真当作后端、权限或医疗能力证据。
- 本次不改变一个 Spec 节点对应一个人工目标的现有交互；同一产品决定是否需要多个场景目标另行确认。

## 已否决方案

- 自动场景书签与点击回放：起点和步骤都可能依赖已丢失状态，真实会诊场景已失败。
- 只压缩或重算最短点击路径：仍无法恢复由创建结果、当前对象或条件状态决定的页面。
- 工作台保存页面运行内存：无法跨框架可靠恢复，并会复制业务数据和组件生命周期。
- 绑定后要求用户刷新验证：增加流程但不修正原始页面缺少精确路由的责任。

## 回归检查

- MDT 的“提交我的意见”页面具有精确地址；在新页面直接打开该地址即可看到同一按钮。
- 用户在目标页面人工绑定后，刷新工作台并点击 Spec 卡片可重新进入该页面并只定位目标。
- 自动候选无法确定页面时仍允许用户手动浏览和绑定；绑定不会执行原页面动作。
- 旧点击书签不再参与状态、导航或提示；原有页面树、候选、拖拽、保存、PRD 和只读评审流程保持可用。
