# ADR-0007：批次独立排队，处理中只能停止

## 背景与问题（Context and Problem）

用户已确认：多处选区评价先收集成一批，显式发送后继续编辑下一批。等待中的批次可撤回编辑；进行中的批次不可撤回，只能停止。原实现把提交等同接收并锁定整个编辑器，不能表达这些区别。

## 决策驱动因素（Decision Drivers）

- 保留原 HTML 画布、缩放/拖拽、可拖宽 PRD 抽屉和就地评价；不另建页面或任务。
- 草稿与已提交批次隔离；断线、重启、新版到达不丢意见。
- 本机收件、原任务领取、请求停止、确认停止是不同事实。
- PRD 正文仍由原任务修订，服务不能回滚已写入文件。

## 候选方案（Considered Options）

1. 持久化批次队列，原任务经 MCP 原子领取并确认停止。
2. 前端改变按钮文案但仍整页锁定：否决，不能持续收集。
3. 点击停止直接标记已停止或通过另起任务接管：否决，没有执行证据且改变原任务所有权。

## 决定结果（Decision Outcome）

采用方案 1。会话 reviewing/ended 与批次状态分开。schemaVersion 2 保留 v1 历史；旧 submitted 因缺少领取记录，迁移为 needs_review，不能假设无人处理后自动再次执行。

```text
原 HTML 画布（既有控制条）   原 PRD 抽屉（可拖宽）
                            正文 → 选区旁评价 → 加入草稿
                            ┌ 第 1 批 处理中 [停止]    ┐
                            │ 第 2 批 等待中 [撤回编辑]│
                            └ 当前草稿 [预览] [发送整批]┘

queued → processing → published
   ↓          ↓
withdrawn   stop_requested → stopped（仅原任务确认）
   ↑
needs_review（旧版或旧协议无接收证据；核对后新批次提交）
```

同一会话最多一个 processing/stop_requested。wait_prd_feedback 在返回批次前原子领取；撤回与领取串行竞争，先落盘者生效。已领取批次不会因超时/断线被重新入队。提交以批次 ID 幂等；停止和撤回也可安全重试。服务不以浏览器轮询判定任务在线。

停止采用合作确认：浏览器持久化请求，原任务使用 get_prd_feedback_status 在修订步骤之间及写入前检查，停止后 acknowledge_prd_stop；未确认一直显示“正在请求停止”。该协议不是桌面原生 turn/interrupt，不能强行终止正在运行的命令。不得通过私有接口、handoff 或新建任务伪装原生停止。已写内容保留；发布与停止请求互斥。安装版本尚未注册新工具时，页面只显示本机等待，不声称已建立真实原任务通道。

每批保留基准 revision/source。2026-09-08 起，本会话正常发布后的队列衔接由统一 Spec `ARCH-PRD-QUEUE-CONTINUE-001` 替代：已发送批次保持排队，保留原始快照并对照当前新版处理。外部重新载入仍进入 needs_review，由用户核对；不静默改写原始反馈。当前浏览器草稿按会话暂存，不随 revision 重建。显式“核对并适配新版”只迁移完整原文上下文唯一匹配的选区；冲突保留全部意见，要求重新选区，不猜测。撤回批次仍存历史，新草稿非空时不覆盖，可稍后取回编辑。

明确不改：HTML 完成协议、Skill 路由、正文/Map 所有权、主干和已安装插件。批次中的引文/意见是数据，不是工具系统指令。

## 后果（Consequences）

### 正向影响（Positive）

- 发送不阻塞下一批编写；队列状态有接收与执行证据。
- 恢复和停止不覆盖 PRD 或当前草稿。

### 负向影响与风险（Negative / Risks）

- 旧版意见需显式核对，安全优先于自动连续覆盖。
- 原任务断线时停止不会即时确认；用户仍可在 Codex 中直接停止。源代码协议验证不代表已安装插件的真实接入验证。

## 验证遵循情况（Confirmation）

- 服务/MCP：多批、并发领取/撤回、停止/发布竞态、错误批次、重复请求、重启、旧状态迁移和来源隔离。
- 浏览器：继续输入、队列预览、撤回不覆盖新草稿、处理中无撤回、停止确认前不假报、旧版草稿保留、原控件回归。
- 运行 npm run verify；三个反向审核分别检查状态所有权、数据保留、真实通信证据。模拟消费者测试不充当原任务原生中断测试。
- 2026-09-02：统一验证通过 112 项 Node 测试与 7 条浏览器旅程；补测旧 save/submit 客户端的过期草稿拒绝。原试用地址恢复后，两条未处理意见完整保留并展示为待核对。三轮自检修正了跨批次版本误拒、旧草稿版本归属和发送成功但回包丢失后的重复草稿问题。已安装插件仍未注册本分支的 PRD 工具，未宣称真实桌面任务原生停止通过。
