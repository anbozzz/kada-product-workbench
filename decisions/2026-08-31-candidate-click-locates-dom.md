# 点击候选 Spec 必须定位对应 DOM

> 后续边界：自动跨页遍历已由 [`2026-09-01-low-confidence-candidate-no-auto-navigation.md`](2026-09-01-low-confidence-candidate-no-auto-navigation.md) 替代；当前页候选定位和显式高置信路由定位继续有效。

## 原因

自动候选的产品价值是帮助用户核对“这个 Spec 是否对应页面上的这个功能”。如果点击候选卡片只打开右侧详情，没有把画布滚动到候选 DOM 并高亮，用户仍需自己在页面中寻找目标，候选评分也无法被直观验证。

## 决定

- 点击存在自动候选的 `SURFACE` / `ACTION` 卡片后，保持该 Spec 为当前选中节点，并打开“页面映射”详情。
- 工作台自动把候选 DOM 滚动到 iframe 可视区域中央，并持续显示醒目的候选轮廓和“候选定位”标签。
- 这一步只用于定位与核对，不进入任意 DOM 选择模式，也不写入 `spec-map.json`。
- 用户点击“确认映射”或整页批量确认后，才生成正式 selector、指纹与确认状态。
- 已确认映射继续沿用原有 selector 定位和高亮逻辑。
- 当前识别页面已经算出的唯一候选不再受 96% 阈值阻断；置信度只决定批量确认建议，点击定位直接使用现有结果。
- 对没有可见文字和无障碍名称的图标按钮，只识别少量稳定、明确的意图类名（如 `plus/add/create/new`），把它们作为低于显式语义属性的候选证据；不会因此自动确认映射。
- 跨页面定位优先使用 Spec 页面已有的本地 hash/query `routeHints`，命中后缓存目标路由和 selector；只有没有当前页候选、没有可用直接路由且缓存缺失时才启动受限探查。
- “首次查找”只描述多状态安全探查，不描述已知路由的页面加载；只有直接 `routeHints` 全部未命中、真正开始受限探查后才允许延迟显示。

## 明确不改

- 不因选中候选而自动确认映射。
- 不执行候选 DOM 自身的点击动作。
- 不改变歧义候选的人工选择路径，也不把像素坐标写入 Map。
- 不把候选 selector 或导航缓存写入 `product.spec.json`；JSON 仍只保存语义投影和页面提示，运行时缓存随会话失效。

## 回归检查

- 点击候选卡片后，对应 DOM 进入可视区域并出现唯一候选高亮与标签。
- 右侧仍显示“确认映射”，Map 文件保持为空。
- 点击非候选或已确认节点不产生错误的候选标签。
- 键盘 Enter/Space 选中候选时获得相同定位结果。
- 当前页图标候选点击不创建探查 iframe；直接路由和路径缓存命中从始至终不出现“首次查找”。
