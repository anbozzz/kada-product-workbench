# 单条内容编辑与本地视图偏好

## 原因

完整节点编辑适合一次调整标题、状态、来源、匹配提示和多段正文，但只修订一个内容块时成本过高。画布快捷操作提示需要帮助首次使用者，又不应在用户已经理解操作后长期占据底栏。

## 决定

- 只读展示中的内容块允许双击进入单条编辑；编辑态原位显示当前块的字段名称与内容，并提供明确的保存、取消动作。
- 单条保存基于当前节点生成补丁，只替换目标块；当该块是状态、来源、概括性定义或页面匹配提示的可见镜像时，同步更新对应结构化字段，避免 JSON 与 Markdown 分叉。保存继续复用现有节点级 revision 校验、普通会话原子写回和 gate 会话草稿语义。
- 完整节点编辑入口继续承担全局字段与内容块结构调整；两种编辑态互斥。
- 单条编辑不在失焦时自动保存，`Escape` 取消，`Ctrl/⌘ + Enter` 明确保存。
- 画布操作提示使用带版本的浏览器本地偏好记录关闭状态；关闭后移除整条底栏占位，只保留右下角悬浮操作条。它属于视图状态，不进入 Markdown、JSON 投影或 Map。

## 明确不改

- 不新增内容块级服务接口、持久化字段或第二份 Spec 数据。
- 不改变 Markdown、JSON 投影和 Map 的所有权与写回方向。
- 不把浏览器引导偏好同步到项目或其他浏览器。

## 否决方案

- 不采用双击后自动保存或失焦保存，避免误触直接改写正式 Markdown。
- 不为单条编辑创建平行数据存储，否则会产生与完整节点编辑之间的版本分叉。

## 回归检查

- 双击一个内容块后只出现一组单条编辑控件，取消不写文件，保存只改变目标项且保留其余块；结构化镜像字段同步保持一致。
- revision 冲突仍由现有保存链拒绝，错误留在当前编辑态。
- 提示首次可见，关闭并刷新后不再出现；清除对应本地偏好后可重新出现。
- 完整编辑、Map 自动保存和 gate 草稿提交流程保持可用。
