# PRD 独立阅读、页面映射与内部 Spec 投影

> 2026-09-01 更新：下文“格式修复不自动创建新的 Codex 任务”条款已被 [ADR-0002](ADR-0002-visible-codex-prd-normalization-draft.md) 取代。现行流程只在用户明确点击后创建可见 Codex 任务，并且只生成 `drafts-documents/` 下的新草稿；原 PRD 仍不改写。其余决定继续有效。

## 原因

当前工作台只能在已有 Spec 和 `product.spec.json` 投影的前提下查看产品信息。PRD 虽然可能已经完整描述产品，但研发无法从页面直接进入相关功能说明；同时，较粗的 Spec 不能覆盖 PRD 全文，继续把 PRD 内容塞进 Spec 的“关联约束”会混淆两种文档的职责。

## 决定

- PRD 是可独立阅读的正式产品文档，不依赖 Spec 存在。工作台从当前页面提供“相关 PRD”入口，并以只读 Markdown 预览呈现目录、检索、当前章节定位、版本和状态。
- PRD 是既有工作台上的增量能力，不是另一种替代工作台。项目同时存在 PRD 与 Spec 时，必须保留绑定/评审切换、Spec 树、页面画布、定义与关联约束、候选定位和保存等原能力，再增加“相关 PRD”入口。
- 可映射 PRD 采用固定层级：`业务功能域 → 页面或关键交互区域 → 功能说明 / 入口与页面 / 用户操作与产品结果 / 必要规则`。映射单元是“页面或关键交互区域”章节。
- 每个可映射功能章节和全局规则章节使用隐藏、稳定、中文语义 ID，例如 `需求-会诊-发起并完成会诊`、`规则-患者身份-当前患者`。标题、排序或章节编号变化不改变该 ID。
- `prd-map.json` 与 PRD 保存在产品文档目录并一起冻结，只保存页面上下文到 PRD 章节 ID 的关系，不复制 PRD 内容。它与节点到 DOM 的 `spec-map.json` 分开。
- Spec 在文档头记录来源 PRD 及其版本；每个 Spec 节点记录一个或多个关联 PRD ID。节点仍通过 `spec-map.json` 定位到具体 DOM。
- `interactive-product-spec` 在既有“读取 PRD”步骤内完成结构校验和范围内覆盖检查；不增加独立覆盖服务或持久化覆盖结果。
- 工作台只允许符合本项目 PRD 格式合同的文档进入 PRD 页面模式并建立 `prd-map.json`。格式不合格时保留原文件和精确错误，绑定失败关闭；用户明确点击后可创建可见 Codex 对话，调用 `$product-documentation` 在 `drafts-documents/` 生成标准化 PRD 草稿，重新校验通过后再绑定。
- `product.spec.json` 不再作为项目内的用户可见产物或项目中心必选文件。工作台可以从 Markdown Spec 生成可重建的工具侧内部投影；兼容已有内部投影和测试夹具，但不把它表述为正式产品资产。
- 选择或更换 Markdown Spec 时不得静默清空已经发现的兼容内部投影。已经选择 Markdown Spec 但内部投影尚未准备完成时，来源确认必须停留在同一步完成恢复或生成，不得以 PRD 存在为由降级进入空 Spec 工作台。
- 插件交付同时包含 `product-documentation` 与 `interactive-product-spec`，使文档标准化与 Spec 生成在同一项目环境中可用。

## 边界与明确不改

- 不新增“需求单元”对象，不新增 PRD 或 Spec 的自动审批状态。
- 不把 PRD 内容复制到 `prd-map.json`、`spec-map.json` 或 Spec 的关联约束中。
- 不根据格式校验、实现状态或文件名自动 Confirm；冻结仍由用户明确确认触发。
- 不因扫描或格式错误自动创建 Codex 任务；只有用户明确发起后才生成独立草稿，不调用 Skill 重写原 PRD。
- 不把“PRD 可在没有 Spec 时独立使用”解释为“PRD 存在时可以隐藏、跳过或替换已有 Spec 能力”。
- 本次只定义并实现产品文档、映射、预览和内部投影的责任边界，不改变后端业务、医疗规则、权限或产品功能本身。

## 否决方案

- 否决“必须先有 Spec 才能读 PRD”：它会让较粗 Spec 成为产品信息瓶颈。
- 否决“把完整 PRD 放进 Spec 关联约束”：重复事实源，且无法形成稳定的页面到 PRD 章节关系。
- 否决“支持任意 PRD 并由模型自动猜测章节”：映射不可重复验证，错误也无法精确反馈。
- 否决“单独建设 PRD → Spec 覆盖检查层”：读取 PRD 的 Skill 已具备调用时机和对象，独立服务只会制造重复状态。
- 否决“在项目内继续要求 `product.spec.json`”：它是可重建投影，不应成为研发需要理解和维护的正式文件。

## 回归检查

- 没有 Spec 时，合法 PRD 仍能进入页面工作台、建立页面关联并打开完整预览。
- 没有 PRD 时，已有 Spec 页面映射能力保持可用；没有 Spec 时不得出现 Spec 节点映射操作。
- PRD 与 Spec 同时存在时，从原工作台入口能同时使用全部 Spec 绑定/评审能力和“相关 PRD”，选择 Markdown Spec 不会清空已有内部投影。
- 已选择 Markdown Spec 但缺少内部投影时不能进入降级工作台；恢复或生成投影后才可进入。
- 不合法 PRD 能得到精确的结构错误，不能创建或写入 `prd-map.json`，原文不被改写。
- PRD 标题、顺序或正文改变但 ID 保持不变时映射保留；ID 删除或重复时关系进入复核提示。
- PRD 与 `prd-map.json` 位于同一产品文档目录；Spec 与 `spec-map.json` 继续保持独立。
- 项目中心不再要求用户选择或维护 `product.spec.json`；内部投影仍经过 Schema 与语义校验。
- 两项 Skill 的格式、引用和失败关闭说明一致，且通过 Skill 校验。
- `npm run verify` 通过；验证结果只证明合同与工作台交互回归，不替代用户验收。
