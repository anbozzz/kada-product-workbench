# ADR-0005：HTML 交付必须完成本轮文档同步

用户主要通过页面反馈逐步形成产品决定。若每轮仍选择 PRD、Spec 或跳过，连续修订后再补文档会依赖不完整的聊天上下文；选择记录也不能证明文档已经处理。用户已要求移除原选择弹窗，将两份文档的同步纳入同一轮交付。

保留 `SessionStart → Agent 显式 publish_html_ready`，由实际执行任务的 Agent 按共享 Spec 标准完成交付文件检查后上报。上报工具只校验指定 Project、HTML 路径和 revision，固定返回 `document-sync-required`：当前任务先按 `product-documentation` 核对 PRD，再按 `interactive-product-spec` 核对统一 Spec，完成受影响修订及一致性检查后才能宣布本轮完成。工具返回不表示文档已同步。

不再发起文档、PRD 类型或跳过对话，不保存选择记录、不按旧决定去重。重复上报仍要求核对当前文件，以便中断后重试；旧 `prdFollowup` 输入仅兼容形状，不再免除 Spec 核对。旧状态文件不读取、不迁移、不删除。压缩 Skill 保留给明确的压缩请求。

同步以本轮明确反馈、当前正式文档和实际页面差异为依据，按影响更新，已有覆盖时说明无需修改；探索结果保留候选。开始后续修订或恢复任务先读当前文件；保留稳定 ID、有效引用、工程章节与人工 Map。非产品 HTML 由 Skill 判断不适用，不凭空建立产品文档。发生文档冲突或写入失败时继续可完成部分，明确剩余差异，不能报告同步完成。

本次不改工作台入口、手工映射、评审及两种 Spec 写回策略；不增加文件监听、同步数据库、审批状态或新文档种类。拒绝继续保留选择/跳过，也不采用“每写一次文件就同步”的监控方式：同步发生在本轮可交付时，不在中间构建或测试写入时。

回归覆盖：连续十轮与相同 revision 重试、旧选择记录和 covered 声明均返回两份文档的待同步要求；有无表单能力都无弹窗；非法路径失败关闭；真实 MCP 协议、SessionStart 和既有工作台统一验证。发布使用新版本包并核对实际安装副本，安装结果不替代新任务接入验收。
