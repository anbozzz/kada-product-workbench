# 本地演示 HTML 的自动场景书签

> **状态：已取代。** 真实 MDT 会诊场景证明，同一路由下记录用户点击历史无法稳定恢复页面内存状态。现行决定见 [`2026-09-01-cold-start-review-routes.md`](2026-09-01-cold-start-review-routes.md)。本文件仅保留失败路线及取代原因，禁止继续作为实现依据。

## 原因

人工页面映射已经保存了组件的 selector、语义指纹和当时 URL，但许多单页演示把“当前患者、只读或编辑态、当前会诊、已展开详情”等场景只保存在页面运行内存中。刷新后即使 URL 不变，页面也会回到默认场景，因此工作台会把仍然正确的人工映射误报为“当前页面未找到”，点击 Spec 也只能回到错误的默认页面。

继续补 URL、扩大自动跨页检索，或在绑定后要求用户刷新验证，都不能补回这段场景信息。

## 决定

- `spec-map.json` 仍以人工确认的目标组件为事实，在 Annotation 的 `target.context` 中增加可选 `sceneBookmark`：保存稳定起点和用户到达绑定场景时实际走过的语义点击步骤。
- 只对工具直接托管且可写映射的本地静态 HTML（运行目标 `targetSourceType: html`，包括直接指定 HTML 与目录项目中的已选 HTML）被动记录；本地开发服务和可移植只读评审包不记录、不回放。
- 记录只发生在用户正常操作页面时，不搜索未知页面，不触发额外验证；不保存输入值、鼠标坐标或页面业务数据。
- 人工点选、拖拽或确认当前页候选时，工作台把当时路径随映射一起保存，并从路径中排除被绑定的目标本身。人工映射写入后立即清除该节点的旧候选结果。
- 点击已有映射时先检查目标是否已经在当前场景；若不在且有书签，则从书签起点重新载入，按顺序回放可验证的本地场景步骤，最后只聚焦和高亮绑定组件，不点击绑定组件。
- 有场景书签但当前默认场景尚未恢复时，状态表示“待进入对应页面”，不再误计为“需复核”；selector 重复、组件语义变化或书签回放失败仍明确提示。
- 旧映射保持兼容。它的目标在用户正常浏览中再次准确出现时，工作台自动补记当前场景书签，不要求解除后重绑。
- 单个书签最多保存 24 个步骤；回放前逐步校验 selector、语义指纹和本地安全边界，任一步不一致即停止，不猜测替代组件。

## 明确不改

- 不修改被评审 HTML 的业务代码，不要求演示项目为每个场景增加路由或持久化状态。
- 不改变人工绑定的 selector 与语义指纹，不把书签当作第二份组件映射。
- 不恢复表单输入值，不回放保存、删除、提交、结束、上报等完成性动作，也不用于真实服务。
- 不恢复已经移除的多状态自动遍历，不因 Spec 文案相似度去试点页面控件。
- 不增加“绑定后刷新验证”步骤，不增加新的页面、模式或平行工作流。

## 否决方案

- 只清除旧推荐：能解决按钮状态冲突，但刷新后仍不知道应恢复哪位患者或哪个业务场景。
- 只保存 URL：动态场景共用同一 URL，仍会回到默认数据。
- 为每个演示 HTML 编写患者、会诊等专用适配器：目标项目一变就失效，维护成本会转嫁给每个演示。
- 自动遍历页面寻找目标：会重新引入等待、误点击和错误跳页。
- 保存 DOM 快照、框架内存或 Local Storage：会复制业务数据，且无法可靠恢复事件和组件生命周期。

## 回归检查

- 从原工作台入口完成“进入动态场景 → 人工绑定 → 自动保存 → 刷新工作台 → 点击 Spec”，能回到同一场景并高亮目标，目标动作本身未执行。
- 刷新后的默认场景不再把带书签的映射计入“需复核”。
- 用户重新绑定后旧候选不再覆盖人工结果；旧 Map 可直接读取，并能在自然浏览到正确场景时自动补齐书签。
- 回放不会写输入值、点击绑定目标或执行明确的完成性动作；步骤漂移时停止并给出可理解的提示。
- 开发服务、只读模式、当前页候选、显式 routeHints、拖拽、解除映射、Map 自动保存和 revision 冲突保护保持原行为。
- `npm run verify` 与真实浏览器旅程通过，并在动态同路由测试页验证刷新恢复。
