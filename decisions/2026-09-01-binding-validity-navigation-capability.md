# 关联事实与自动跳转能力分离

## 原因

现有工作台把“绑定地址可以在新窗口冷启动并重建同一业务状态”设为人工关联的前提。这要求产品经理制作的低保真 HTML 保存患者、会诊、表单和临时流程状态，实质上把演示原型当成完整应用。

低保真页面通常只保证功能能够通过演示路径进入，不保证刷新后恢复任意运行时状态。继续坚持冷启动门槛会让已经由用户确认的组件关联，因为页面暂时没有进入对应演示场景而被误报为失效。

## 决定

- `spec-map.json` 中用户确认的 `Spec 节点 → selector + fingerprint` 是长期关联事实；保存的页面地址只用于尽力导航，不是关联成立的条件。
- 人工点选、拖拽和批量确认不再检查来源 HTML 是否声明可冷启动，也不要求页面提供运行态恢复协议。
- 点击已关联节点时，工作台先尝试打开保存地址并定位组件；只要保存地址仍可自动打开，即使目标尚未出现在当前 DOM，也保持显示“已关联”。只有已到达保存地址或没有可用地址、目标仍未出现时，才显示“已关联 · 需手动进入”，提示用户在中间页面进入动态场景。
- 用户手动进入场景后，工作台按原 selector 与 fingerprint 自动恢复定位和高亮，不要求重新绑定。
- selector 零命中只证明当前场景未显示目标：存在不同的可自动打开保存地址时保持 `confirmed`；自动导航不可用或已到达保存地址后才归为 `out-of-context`，两者都不进入“需复核”。selector 多命中、命中元素不再是兼容目标，或唯一元素的语义指纹变化，仍分别进入不唯一、无效或漂移复核。
- 原始 HTML 有稳定 hash/query 时继续作为自动跳转增强；没有稳定路由时仍可完整建立和保存人工关联。

## 明确不改

- 不保存、搜索或回放用户点击过程，不保存 DOM 快照、页面内存或表单数据。
- 不执行被绑定组件，不遍历未知页面寻找目标。
- 不改变 `spec-map.json` Schema、selector、fingerprint、revision 保存和并发保护。
- 不把低保真页面当成后端、权限、接口或业务闭环证据。
- 不调整 MDT 项目的 HTML Handoff；本决定只修改 Interactive Product Spec 的通用映射职责。

## 已否决方案

- 强制所有 HTML 补齐可冷启动路由：超出产品经理低保真演示的合理制作责任。
- 绑定后刷新验证：增加流程但仍要求原型具备完整状态恢复。
- 页面快照或录像：只能回看，不能继续操作。
- 点击轨迹回放：不能可靠恢复动态对象、输入和条件状态。

## 回归检查

- 不提供任何精确路由协议的动态演示场景仍可人工绑定并自动保存。
- 刷新回默认场景后，关联计入已映射，不进入“需复核”，显示需要手动进入场景。
- 用户再次手动进入场景后，原组件自动恢复为已确认并高亮，不需要重绑，Map 内容不变。
- 有稳定路由的页面仍可尽力自动跳转，且不会执行目标动作。
- 自动候选、批量确认、重新关联、解除映射、PRD 阅读、Spec 编辑、只读评审、导出和保存冲突保护保持可用。
